# 要件定義: 会場情報取得(F14)

- ステータス: draft
- 作成日: 2026-09-29
- 更新日: 2026-10-02(住所抽出を廃止。F09のライブ情報を手がかりとして受け取る形に変更。spec 011のコーデ提案に組み込み)

## 1. 背景 / 課題

コーディネート提案(F20: 統合スタイルプロファイル生成)は、会場・天気情報を統合して提案の材料にする設計になっている。そのうち「会場の形態(スタンディング/着席等)」を取得するのがF14の役割。

実アプリでは、会場名はユーザーが直接入力するのではなく、F09(ライブ情報の検索)が返す `LiveCandidate`(`venue`・`location`・`live_name`・`date`)から得る。F09は会場名と所在地(都道府県・市区町村)までは返すが、座席形態は調べていない。F14はその会場名を受け取り、座席形態を深掘りして返す。

変更履歴:
- 当初は、F15(天気情報取得)の入力として会場の住所も取得する想定だった。その後、天気は外部APIを使わずユーザーの任意入力とする方針になり、住所の用途がなくなったため、住所抽出は廃止した(2026-10-02)。
- 座席形態は会場だけでなく公演ごとに決まることが多く、同名・複数拠点の会場(市民ホール、Zepp等)もあるため、F09の所在地・ライブ名・公演日を検索の手がかりとして任意で受け取れるようにした(2026-10-02)。

## 2. ゴール / 非ゴール

### ゴール
- 会場名(文字列)を入力として受け取り、会場の形態(スタンディング/着席/不明)を含む会場情報を取得できるようにする。
- 所在地・ライブ名・公演日を任意の手がかりとして受け取り、渡された場合は検索に反映して精度を上げる。未指定でも動く。
- 既存の実装パターン(`services/wardrobe.py` 等)に合わせ、「コアロジック関数」と「ADKツールとして登録する薄いラッパー関数」を分離して実装し、呼び出し方(エージェントの自律呼び出し / Orchestratorからの明示呼び出し)を問わず再利用できる形にする。
- 取得に失敗しても例外で落とさず、「形態不明」として扱ってサービス全体を止めない。

### 非ゴール
- 会場の住所・緯度経度の取得(天気APIを使わない方針になったため不要)。
- F09の結果をF14に渡す処理そのもの。spec 011(コーデ提案)の `OutfitService.suggest` が、選んだライブの情報をF14に渡して呼ぶ(2026-10-02)。F14は引数で手がかりを受け取るところまで。
- F20への実際の受け渡し方式の確定は対象外(本specはF14単体のロジック実装まで)。

## 3. ユーザーストーリー

- `コーディネート提案の仕組み(エージェント/Orchestrator)` として、`ライブの会場名(と分かれば所在地・ライブ名・公演日)から会場の形態を把握` したい。なぜなら `会場の形態(スタンディング/着席等)がコーディネート提案の判断材料になる` から。

## 4. 受け入れ基準

- [x] AC-1: Given 会場名(例: "日本武道館")が渡されたとき, When 会場情報取得のコア関数を呼び出すと, Then 会場の形態を含む会場情報が返る。
- [x] AC-2: Given Gemini APIからの取得に失敗する状況(異常系), When 関数を呼び出すと, Then 例外を投げず「形態不明」として扱った結果を返す。
- [x] AC-3: Given 実装したコード, When `wardrobe.py`等の既存実装と比較すると, Then コアロジック関数とADKツール登録用ラッパー関数が分離されている。
- [ ] AC-5: Given 会場名に加えて所在地・ライブ名・公演日の一部または全部が渡されたとき, When コア関数を呼び出すと, Then それらが検索プロンプトに含まれる。渡されなかった場合は従来どおり会場名だけで動く。
- [x] AC-6: Given コーデ提案(spec 011)でライブを選んで「コーデを提案」を押したとき, When 提案を作ると, Then 会場の形態(スタンディング/着席)が分かれば提案のプロンプトに含まれる。分からない・失敗・時間切れの場合は形態なしで提案され、提案全体は失敗しない。
- (廃止) ~~AC-4: 住所(または緯度経度)を含む会場情報が返る~~ → 2026-10-02 に廃止(天気APIを使わない方針のため)。

## 5. 制約 / 前提

- 技術制約: Gemini API(Web検索)を使用する。既存のADC認証パターンをそのまま利用し、追加の外部APIキーは不要。
- 依存する spec: spec 009(ライブ情報の検索)。F14自体は依存しないが、実アプリでの入力元(`LiveCandidate`)として想定している。
- 参考: 機能一覧表(ライブ用服装エージェント_機能一覧.xlsx) F14行、検討メモ(work_space/検討/F14-16_MVP優先度検討メモ.md)。

# 要件定義: アーティストのカルチャー情報を Gemini で調べて整理する

- ステータス: approved
- 作成日: 2026-09-29
- 更新日: 2026-09-29

## 1. 背景 / 課題

spec 007 で、MV からアーティスト名・曲名などが揃うようになった。
最終的には「このアーティストらしい服装」を**手持ちの服で提案**したい(後続の spec。服インデックスは spec 005 / 006)。
そのためにはアーティストの**ファッション・ビジュアルの傾向**と、その背景にある**経歴・音楽性**を知る必要があるが、
YouTube の情報(タイトル・概要欄)だけでは分からない。利用者が自分で検索して回るのも手間がかかる。

そこで、動画が決まったら Gemini に **Google 検索**でアーティストを調べさせ、さらに **MV の映像そのもの**から衣装を読み取らせて、
**項目ごとに整理した形**で得られるようにする。

## 2. ゴール / 非ゴール

### ゴール
- 動画情報が表示されたら(**URL を入力したとき・候補を選んだとき**)、**操作なしで自動的に** Gemini が調べ始める。
- 調べる内容は「**ファッション・ビジュアル**」と「**経歴・音楽性**」の 2 分類。
- アーティスト全般の情報は **Google 検索(グラウンディング)**で Web の最新情報を根拠にし、**出典(ページのタイトルと URL)**を残す。
- **MV の映像を Gemini に見せて**、その MV で着ている衣装(アイテム・色・系統)を読み取る。
- 結果は**項目ごとに整理した構造化データ**にする。ファッションの項目(色・系統・アイテム)は、
  後続のコーデ提案で服インデックスと照合しやすい語(例: 「黒」「ストリート」「ブーツ」)で書く。
- 調べている間は**回転するローディング表示**を出し、MV 検索画面は**他の入力を受け付けない**(入力欄・検索ボタン・候補の選択・「候補一覧に戻る」)。

### 整理する項目

| 分類 | 項目 | 内容 | 根拠 | 例 |
| --- | --- | --- | --- | --- |
| 共通 | 調べたアーティスト名 | Gemini が特定したアーティスト名 | Web 検索 | YOASOBI |
| ファッション・ビジュアル | スタイルの傾向 | 衣装・私服の系統 | Web 検索 | ストリート、モード、ガーリー |
| | よく使う色 | 衣装・アートワークに多い色 | Web 検索 | 黒、白、パステルカラー |
| | 定番のアイテム | そのアーティストを象徴するアイテム | Web 検索 | ベレー帽、厚底ブーツ |
| | ビジュアルの世界観 | MV・アートワークに共通するモチーフや雰囲気 | Web 検索 | 近未来的、レトロ |
| | **この MV の衣装** | この MV で着ている服(アイテム・色・系統) | **MV の映像** | 黒のロングコート、白のスニーカー |
| 経歴・音楽性 | 概要 | どんなアーティストか(1〜2 文) | Web 検索 | — |
| | 活動の歩み | 結成・デビューの年、主な出来事 | Web 検索 | — |
| | ジャンル | 音楽のジャンル | Web 検索 | J-POP、ロック |
| | 代表曲 | 代表的な曲(数曲) | Web 検索 | — |
| | 音楽的な特徴 | 作風・影響を受けたものなど | Web 検索 | — |
| 共通 | 出典 | 参照した Web ページのタイトルと URL | Web 検索 | — |

### 非ゴール
- コーデ提案そのもの(後続の spec で扱う。本 spec は情報の取得と整理まで)。
- ファン文化(ファンの呼び名・メンバーカラー・ペンライトなど)と公演情報。
- **結果の保存・使い回し**。Google 検索のグラウンディング結果を保存すると利用規約上の問題になるおそれがあるため、
  動画を表示するたびに調べ直す(同じアーティスト・同じ動画でも使い回さない)。
- 情報の正確さの保証(Web 情報の要約と映像からの推定であるため、出典を示すところまで)。
- チャットのエージェントのツールとしての提供。

## 3. ユーザーストーリー

- 利用者として、MV を選んだら、そのアーティストのファッションの傾向と人物像がまとまって見たい。自分で検索して回るのは手間だから。
- 利用者として、その MV で実際に着ている服も知りたい。真似したい服装はその MV のものだから。
- 利用者として、情報の出典を確認したい。Gemini の要約が正しいか確かめたいから。
- 開発者として、後続のコーデ提案に、色・系統・アイテムなどを照合しやすい形で渡したい。

- [ ] AC-4: Given 取得が完了した, When 画面を見る, Then Web 検索で参照したページの出典(タイトル・URL)が 1 件以上表示される。
- [ ] AC-5: Given 公開されている MV, When 取得が完了した, Then MV の映像から読み取った「この MV の衣装」(アイテム・色・系統)が表示される。
- [x] AC-6: Given 映像を解析できない動画(非公開・年齢制限など), When 取得, Then Web 検索による項目は表示され、「この MV の衣装」の欄に解析できなかった旨が出る。
- [x] AC-7: Given タイトルを分解できなかった動画(アーティスト名 = チャンネル名), When 取得, Then 動画タイトル・概要欄も手がかりにアーティストが特定され、特定したアーティスト名が表示される。
- [x] AC-8: Given 音楽と関係のない動画などでアーティストを特定できない, When 取得, Then 推測で埋めずに「特定できなかった」旨が表示される。
- [x] AC-9: Given Gemini または検索の失敗(クォータ超過・タイムアウトなど), When 取得, Then 動画情報はそのまま表示され、カルチャー情報の欄にエラーと再試行ボタンが出る。

## 5. 制約 / 前提

- Gemini は Vertex AI 経由で呼ぶ(認証は ADC。spec 001)。検索は **Grounding with Google Search** を使う。
  グラウンディングはモデル呼び出しとは別に課金される。**使い回さないため、動画を表示するたびに課金が発生する**(料金は design で確認する)。
- MV の映像は、YouTube の URL を Gemini に渡して解析させる(動画ファイルはダウンロードしない)。
  Vertex AI で YouTube の URL をそのまま渡せるか、動画の長さの上限・消費トークンは design で確認する。
- 映像の解析を含むため、応答には数十秒かかる想定。ローディング表示と待ち時間の上限(タイムアウト)を設ける。
- Gemini に渡す材料は spec 007 の `VideoInfo`(アーティスト名・曲名・動画タイトル・チャンネル名・概要欄・公開日・分解できたか・動画の URL)。
- 取得は「動画情報が表示されたとき」だけ。候補一覧を眺めるだけでは呼ばない。
- 外部 API(Gemini)の呼び出しは `app/services/` に閉じ、テストではスタブにする。
- 依存する spec: [001-gemini-adk-chat](../001-gemini-adk-chat/)、[007-youtube-mv-metadata](../007-youtube-mv-metadata/)。
  後続のコーデ提案で [005-cloth-index](../005-cloth-index/) / [006-wardrobe-tools](../006-wardrobe-tools/) と組み合わせる。

## 6. 決定事項 / 未決事項

### 決定事項(2026-09-29)

| # | 論点 | 決定 |
| --- | --- | --- |
| 1 | 結果の保存・使い回し | しない。グラウンディング結果の保存は利用規約上の問題になるおそれがあるため |
| 2 | MV の映像の解析 | する。「この MV の衣装」を映像から読み取る |
| 3 | 取得を始めるタイミング | 候補を選んだとき、および URL を入力して動画情報が表示されたとき(どちらも自動) |
| 4 | 取得中の操作 | MV 検索画面は他の入力を受け付けない(入力欄・検索ボタン・候補の選択・「候補一覧に戻る」) |
| 5 | Grounding with Google Search の利用条件 | 検索候補(Search Suggestions)の表示が必須。出典は項目の近くと一覧の両方に示す(design.md 0.) |
| 6 | 使うモデル | `GEMINI_MODEL` とは別に `CULTURE_MODEL` を設ける(design.md 6.5) |

# 設計: 画面の作り直し(tadasii のデザインに合わせる)

- 対応する要件: `./requirements.md`
- ステータス: approved
- 更新日: 2026-10-05

## 1. 設計方針

参考 UI(`tadasii/`。Git 管理外)の**画面の部品と構成をそのまま移植**し、中身(呼ぶ API・扱うデータ)は今の feature のコードを使う。

| 案 | 進め方 | 採否 | 理由 |
| --- | --- | --- | --- |
| A | tadasii のテーマ・部品(`theme.dart`・ヘッダー・送信バー・進捗・結果)を移植し、今の各画面を「カード」に作り替えて 1 画面に並べる | 採用 | 見た目を tadasii と一致させやすい。各 feature の Repository・モデル・処理の流れはほぼそのまま使える |
| B | tadasii のコードを丸ごと持ってきて、API の呼び出しだけ差し替える | 却下 | tadasii は別の API(写真と公演情報を 1 回送ると提案まで進む)前提で、データの持ち方が今と合わない。機能が変わってしまう |
| C | 今の画面のまま、配色とテーマだけ変える | 却下 | 要件の決定事項 1(1 画面の流れ)を満たさない |

| 案 | 入力の段階の状態をどう残すか(AC-9・AC-14) | 採否 | 理由 |
| --- | --- | --- | --- |
| A | 入力のカードを `Visibility(maintainState: true)` で隠すだけにし、進捗・結果の段階でも破棄しない | 採用 | 各カードが持つ状態(入力欄・候補・選択・取得中の処理)を今のまま使える |
| B | tadasii のように入力内容を 1 つのオブジェクトに集めて親が持つ | 却下 | MV・カルチャー・ライブ・服の状態を全部作り直すことになり、変更が大きい |

| 案 | 状態管理 | 採否 | 理由 |
| --- | --- | --- | --- |
| A | 今と同じ `setState` / コールバック / `ValueNotifier`。コーデ提案だけ `ChangeNotifier` の小さなコントローラにまとめる | 採用 | 依存を足さない(spec 011 と同じ方針) |
| B | 状態管理パッケージを入れる | 却下 | 依存の追加。要件で認めたのは `url_launcher` のみ |

## 2. 全体フロー

```
App(main.dart: テーマ・タイトル)
 └─ HomePage(lib/app/home_page.dart) ── 段階: input / running / result
     ├─ _Header: ♪ アイコン・「はじめてのライブ服」・説明・段階の Pill(1 入力 / 2 AIが考え中 / 3 提案)
     ├─ [input]  Visibility(maintainState) で常に保持
     │   ├─ _MessageBox(キャンセルの案内 / 足りないもの・エラーの一覧)
     │   ├─ MvLookupPanel ─ ① MV を選ぶ(SectionCard)  ─┐ onChanged(MvLookupSnapshot)
     │   │                └ ② 行くライブを検索(SectionCard)┘
     │   └─ WardrobeSection ─ ③ 手持ちの服(SectionCard) ─── onChanged(List<RegisteredCloth>)
     ├─ [running] OutfitProgressView ─ 段階(コーデを考える → 着せた画像を作る)・経過時間・服の写真・キャンセル
     ├─ [result]  OutfitResultView ─ コーデ名・画像(拡大 / 保存)・使う服・理由・提案に使った情報・やり直し
     └─ bottomNavigationBar: [input のときだけ] _SubmitBar(チェックリスト + 「コーディネートを提案してもらう」)

OutfitController(features/outfit。ChangeNotifier)
  run(video, live, culture) ─ ① POST /outfit/suggest → ② POST /outfit/image(今と同じ順・同じ内容)
  retryImage() / cancel()
```

段階の切り替え:

| きっかけ | 段階 |
| --- | --- |
| 提案ボタン(そろっている) | input → running |
| 提案と画像の生成が終わった(画像だけの失敗を含む) | running →(「コーディネートができました!」を 0.9 秒見せて)→ result |
| 提案が失敗した | running → input(上部にエラー) |
| キャンセル | running → input(上部に「提案をキャンセルしました。入力内容はそのまま残っています。」) |
| 「条件を変えてもう一度」 | result → input |

切り替えるたびに画面の先頭までスクロールする(tadasii と同じ)。

- 44px の角丸(赤 → 紫のグラデーション)に「♪」、横に「はじめてのライブ服」(太字)と説明
  「行くライブと手持ちの服から、会場で浮かないコーディネートを提案します。」。
- 段階の Pill: 今の段階は赤地に白の太字、済んだ段階は薄い茶、まだの段階は白。

### 5.3 ① MV を選ぶ / ② 行くライブを検索(`MvLookupPanel`)

今の `MvLookupScreen` の処理(状態・ロック・要約の通知)はそのままで、表示だけを 2 枚の `SectionCard` に分ける。
両方のカードで状態(取得中のロック・表示中の動画のアーティスト)を共有するため、1 つの StatefulWidget のまま 2 枚を返す。

| 部分 | 今 | tadasii に合わせた後 |
| --- | --- | --- |
| ① の見出し | AppBar「MV 検索」 | ①「MV を選ぶ」+ 説明(URL か MV 名で探す。動画を選ぶとカルチャー情報を自動で調べる) |
| 入力欄 | 枠線の TextField + 丸い検索アイコン | 白地・角丸・虫めがねの TextField(ラベル「YouTube の URL または MV 名」)+ 「検索」ボタン(取得中は回転表示) |
| 入力のエラー | MaterialBanner | 入力欄の下に茶色の文字(tadasii の `_searchError`) |
| MV の候補 | 行の一覧(サムネイル・タイトル) | 薄い茶の角丸タイル(サムネイル・タイトル太字・チャンネル)。展開中は薄い赤地 + 赤い枠 + チェック |
| 動画の情報・カルチャー情報 | Card | 展開した候補の下に、薄い茶の枠で表示(中身は今と同じ項目) |
| ② の見出し | Card「ライブを探す」 | ②「行くライブを検索」+ 説明(アーティストは表示中の動画から) |
| ライブの入力 | 入力欄 + 日付ボタン + 検索アイコン | 入力欄(ラベル「ライブ名・ツアー名・会場など」)+ 「検索」ボタン。公演日は「詳細検索(任意)」を開いた中の欄(タップで日付を選ぶ・× で消す)。閉じていても「・1件入力中」と出す |
| ライブの候補 | 3 件のカード(選ぶと色が変わる) | tadasii の候補タイル(♪ アイコン・ライブ名太字・日付 ・ 会場(場所)・天気・出典番号)。選ぶと選んだ 1 件だけを赤い枠で出し、右に「変更」(タップで選び直せる。3 件の一覧に戻る) |
| 出典・検索候補 | `[1] タイトル(ドメイン)` と URL の文字 | 「参照した情報源:」に続けてタイトルのリンク(タップで開く。AC-18)。検索候補はその下(利用条件のため必須) |

入力の段階では全体が 1 本のスクロールになるため、今の `ListView` は `Column` にする
(ライブの入力が画面外で破棄され、入力した文字が消える問題もこれで起きなくなる)。

| --- | --- | --- |
| 見出し | AppBar「手持ちの服」 | ③「手持ちの服」、右に「N 点」 |
| 説明 | なし | 「服の写真を追加すると、AI が種類・色・素材などを読み取って登録します(1 回 10 枚まで)。」 |
| 一覧 | 写真 + 属性の行のカード | 写真の格子(1 枚の幅 110px まで)。左下に種類のラベル、右上に × (削除。確認のダイアログは今のまま) |
| 属性 | 一覧に常に表示 | 写真をタップすると下から属性のシートが開く(今と同じ項目。spec 010 AC-8 の「主な属性」はここで見る) |
| 追加 | 右下の「写真を追加」 | 格子の下の「写真を選ぶ」(枠線のボタン)。押した後は今と同じ確認画面(全画面)で解析・修正・保存 |

### 5.5 送信バーとメッセージ(tadasii の `_SubmitBar` / `_MessageBox`)

- 画面下に固定。チェックリストは「MV」「ライブの選択」「手持ちの服(N 点)」。そろった項目は緑のチェック。
- ボタン「コーディネートを提案してもらう」は常に押せる(そろっていないときは薄い赤)。押したときに次を確かめる。

| 条件 | 上部に出す文 |
| --- | --- |
| 動画が無い | ① で MV を選んでください。 |
| ライブを選んでいない | ② でライブを検索して、行くライブを選んでください。 |
| 服が 0 件 | ③ で手持ちの服を 1 点以上登録してください。 |
| カルチャー情報の取得中 | カルチャー情報を調べています。終わってからもう一度押してください。 |

- 一度押した後は、足りないものの一覧を入力に合わせてその場で更新する(tadasii と同じ)。
- 提案の失敗(`OutfitController.error`)も同じ枠に出す(AC-13)。

### 5.6 進捗の画面(`OutfitProgressView`)

tadasii の `progress_view.dart` から、**% とバー・豆知識を除いて**移植する(要件の決定事項 8 と非ゴール)。

- 上から: イコライザーの演出(完了したら緑のチェック)、見出し、経過時間(「経過 12秒 ・ 目安 30秒〜1分」)、
  「完了まで、この画面を開いたままお待ちください」、手持ちの服の小さな写真の横並び、段階の一覧、「キャンセルして入力に戻る」。
- 段階は 2 つ。実際の API の完了に合わせて切り替える。

| 段階 | 処理中の見出し | 終わる条件 |
| --- | --- | --- |
| 1 コーデを考える | 手持ちの服から、行くライブに合うコーデを考えています | `POST /outfit/suggest` が返った |
| 2 着せた画像を作る | マネキンに着せた画像を作っています | `POST /outfit/image` が返った(失敗も含む) |

- 150 秒を超えたら「いつもより時間がかかっています。画面を閉じずにそのままお待ちください。」を出す(tadasii と同じ)。
- 画像だけが失敗して終わったときは、見出しを「コーデはできましたが、画像は作れませんでした」、段階 2 を失敗の表示にする
  (T-09 で、失敗でも「できました」と出て紛らわしかったため追加)。

### 5.7 結果の画面(`OutfitResultView`)

| カード | 中身 |
| --- | --- |
| 先頭 | ライブ(ライブ名 ・ 日付 ・ 会場)、コーデ名(大きく)、画像(タップで全画面の拡大。下に「拡大して見る」「画像を保存」(Web のみ))、使う服(写真 52px・役割・種類・理由)、「手持ちに無い服 N 点は提案から除きました」 |
| 画像が失敗したとき | 画像の場所にエラーと「画像を作り直す」(作り直し中はその場で回転表示。段階は result のまま) |
| このコーデを選んだ理由 | 説明(summary)と「ポイント」(箇条書き) |
| MV のファッション | カルチャー情報のスタイル・色・アイテム(Pill)、世界観、この MV の衣装、音楽ジャンル + 出典・検索候補 |
| 会場・天気 | 選んだライブの会場・場所・日付・天気 + 出典・検索候補 |
| 最後 | 「条件を変えてもう一度」 |

広い画面(640px 以上)では「MV のファッション」と「会場・天気」を 2 列に並べる(tadasii と同じ)。
グラウンディングの結果を出す場所には、今と同じく出典と検索候補を必ず添える。

## 7. エラーハンドリング / 非機能

- 各カードのエラー(MV・カルチャー・ライブ・服の読み込み)は、今と同じくカードの中に出す。上部の枠は「提案できない理由」と「提案の失敗」だけ。
- キャンセルはバックエンドの処理を止めない。後から届いた結果は世代番号で捨てる。
- 出典を開けなかったとき(`launchUrl` が false)は、下に「リンクを開けませんでした」と出す。

## 8. テスト方針

| 対象 | 手段 |
| --- | --- |
| `OutfitController` | フェイクの `OutfitRepository` で: 提案 → 画像の順、画像だけの失敗、提案の失敗、キャンセル後の結果を捨てる、作り直し |
| `MvLookupPanel` | 今の MV・カルチャー・ライブのテストを新しい表示に合わせて移す(ロック・候補の展開・自動取得・要約の通知・ライブの選択と「変更」・詳細検索の日付) |
| `WardrobeSection` | 0 件・格子・属性のシート・削除(確認あり)・読み込み失敗・確認画面からの保存で読み直す |
| `HomePage` | 段階の Pill、チェックリスト、足りないときのエラー一覧(4 種)、提案 → 進捗 → 結果、キャンセル、提案の失敗で入力に戻る、画像の作り直し、「条件を変えてもう一度」で入力が残っている、タブが無い |
| `OutfitResultView` | 項目の表示、画像のタップで拡大、Web 以外では「画像を保存」を出さない |
| 見た目 | 幅 390px・1280px でのはみ出しの有無(`tester.takeException()` が無いこと)。目視は T-09 |

イコライザーは止まらないアニメーションのため、進捗の画面を出したままのテストでは `pumpAndSettle` を使わず `pump(時間)` で進める。

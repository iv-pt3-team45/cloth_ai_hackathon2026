# 要件定義: 画面の作り直し(tadasii のデザインに合わせる)

- ステータス: approved
- 作成日: 2026-10-05
- 更新日: 2026-10-05

## 1. 背景 / 課題

spec 007〜011 で、MV の検索・カルチャー情報・ライブ情報・手持ちの服の登録・コーデ提案がそろった。
しかし画面は機能を作るたびに足してきたため、

- 下部のタブが 4 つ(MV 検索 / 手持ちの服 / 確認 / チャット)に分かれ、何をどの順にすればコーデを提案してもらえるかが分かりにくい。
- 配色・見出し・ボタンが Flutter の既定のままで、統一感がない。
- 主な利用場面であるスマホの縦画面を前提にした作りになっていない。

チームで用意した参考 UI(リポジトリ直下の `tadasii/`。Flutter Web のコードと、縦画面で動かしたときの画面イメージ
`01_F01_input.png` など 6 枚。**Git には含めない**)を**正**として、画面を作り直す。**機能は変えない**(バックエンドは改修しない)。

## 2. ゴール / 非ゴール

### ゴール

**A. 画面の流れ(tadasii と同じ 1 画面の流れ)**
- 下部のタブをやめ、1 つの画面で **「1 入力」→「2 AIが考え中」→「3 提案」** と進む。今どの段階かを、画面上部の段階表示で示す。
- 入力の段階では、次のカードを縦に並べる。

| カード | 中身(今の機能) | 元の画面 |
| --- | --- | --- |
| ① MV を選ぶ | YouTube の URL / MV 名で検索、候補の選択、動画の情報、カルチャー情報(自動で取得) | MV 検索タブ(spec 007 / 008) |
| ② 行くライブを検索 | ライブ情報・日付で検索、候補 3 件から選択、当日の天気 | MV 検索タブ(spec 009) |
| ③ 手持ちの服 | 登録済みの服の写真の一覧、写真の追加(解析 → 確認・修正 → 保存)、削除 | 手持ちの服タブ(spec 010) |

- 画面下に**提案ボタンを固定**し、ボタンの上に「MV / ライブの選択 / 手持ちの服」がそろったかのチェックリストを出す。
  足りないまま押すと、画面上部に足りないものを一覧で示す(tadasii の `02_F01_input_errors.png`)。
- 提案ボタンを押すと「AIが考え中」(進捗の画面)に切り替わり、コーデの提案 → マネキン画像の生成の順に、今どの段階かを示す(進み具合の % は出さない)。
  終わると「提案」(結果の画面)に切り替わる。
- 結果の画面には、コーデ名・説明・生成した画像・使う服(写真と理由)・ポイント・提案に使った情報(カルチャー・ライブ・天気)を出す。
  「条件を変えてもう一度」で入力の段階に戻る(入力した内容は残す)。

**B. 見た目(tadasii に合わせる)**
- 配色・角丸のカード・番号付きの見出し・入力欄・ボタン・ラベル(Pill)を tadasii と同じにする。
- アプリ名・説明・アイコン(タブのアイコン・ホーム画面のアイコン)を tadasii の `web/` に合わせる(アプリ名「はじめてのライブ服」)。
- スマホの縦画面を基準にし、広い画面では中央に幅 880px までで表示する。

**C. tadasii にあって今のアプリに無い要素のうち、入れるもの(決定済み)**
- 進捗の画面の「**キャンセルして入力に戻る**」。画面側で結果を受け取らないだけで、バックエンドの処理は止めない。
- 結果の画面の**画像の拡大表示**と、Web での**画像の保存**(ダウンロード)。
- 出典のリンクを**タップで開ける**ようにする(`url_launcher` を追加する)。

### 非ゴール
- 機能の追加・変更・削除(上の C を除く)。API・バックエンドは変えない。
- tadasii にあっても今回入れないもの:
  ライブ服の豆知識 / 上手に撮るコツ / 進み具合の % とバー / 画像利用の同意チェック / 「公式MVの雰囲気も参考にする」の切り替え / 詳細検索のジャンル・会場など今の API に無い条件 /
  手持ちの服の「すべて削除」 / 写真のサイズ表示 / モックモードの表示 / 処理中のスリープ防止(`wakelock_plus`) / 日付選択の日本語化(`flutter_localizations`)。
- **チャットは画面から外す**(エージェントの機能・コードとバックエンドは残す。画面から開けなくなるだけ)。
- 横画面専用のレイアウト、ダークモード。

## 3. ユーザーストーリー

- 初めてライブに行く利用者として、上から順に入力していけばコーデを提案してもらえる画面にしたい。何をすればよいか迷わないから。
- スマホで使う利用者として、縦画面で片手で操作しやすい画面にしたい。会場へ向かう途中などスマホで使うことが多いから。
- 利用者として、提案を待っている間に何が進んでいるかを知りたい。数十秒かかるので、止まっていないか不安になるから。

## 4. 受け入れ基準

### A. 画面の流れ
- [ ] AC-1: Given アプリを開いた, When 画面を見る, Then 下部のタブは無く、ヘッダー(アイコン・「はじめてのライブ服」・説明)と段階表示「1 入力 / 2 AIが考え中 / 3 提案」があり、「1 入力」が選ばれている。
- [ ] AC-2: Given 入力の段階, When 画面を見る, Then 「① MV を選ぶ」「② 行くライブを検索」「③ 手持ちの服」のカードが縦に並び、画面下に提案ボタンとチェックリスト(MV / ライブの選択 / 手持ちの服)が固定されている。
- [ ] AC-3: Given ① のカード, When MV を検索・選択する, Then 今の MV 検索タブと同じ操作(URL / MV 名での検索、候補のその場での展開、カルチャー情報の自動取得と取得中の表示、出典と検索候補の表示)ができる。
- [ ] AC-4: Given ② のカード, When ライブを検索・選択する, Then 今と同じ操作(ライブ情報・日付のどちらかでの検索、3 件の候補からの選択、天気・出典の表示)ができ、選んだ候補が分かる表示になる。
- [ ] AC-5: Given ③ のカード, When 写真を追加・削除する, Then 今の手持ちの服タブと同じ操作(複数枚の選択、1 枚ずつの解析、保存前の確認・修正・除外、保存、確認つきの削除)ができ、登録済みの服が写真で並ぶ。
- [ ] AC-6: Given MV・ライブの選択・手持ちの服のどれかが足りない, When 提案ボタンを押す, Then 提案は始まらず、画面上部に足りないものが一覧で出て、チェックリストの該当項目が未完了のままになる。
- [ ] AC-7: Given カルチャー情報の取得中, When 提案ボタンを押す, Then 提案は始まらず、取得が終わるまで待つよう案内が出る(今と同じ条件)。
- [ ] AC-8: Given 必要なものがそろった, When 提案ボタンを押す, Then 「2 AIが考え中」に切り替わり、「コーデを考える」→「着せた画像を作る」のどの段階かと経過時間が表示される(% は出さない)。
- [ ] AC-9: Given 進捗の画面, When 「キャンセルして入力に戻る」を押す, Then 入力の段階に戻り、入力内容は残り、後から結果が届いても画面は切り替わらない。
- [ ] AC-10: Given 提案と画像の生成が終わった, When 画面を見る, Then 「3 提案」に切り替わり、コーデ名・説明・画像・使う服(写真・役割・理由)・ポイント・手持ちに無い服を除いた件数・提案に使った情報(カルチャー・ライブ・天気)が表示される。
- [ ] AC-11: Given 結果の画面, When 画像をタップする / 「画像を保存」を押す(Web), Then 画像が全画面で拡大表示される / 画像がダウンロードされる。
- [ ] AC-12: Given 画像の生成だけが失敗した, When 結果の画面を見る, Then 提案は表示したまま、画像の欄にエラーと「画像を作り直す」が出る(今と同じ)。
- [ ] AC-13: Given 提案が失敗した, When 画面を見る, Then 入力の段階に戻り、画面上部にエラーが出て、もう一度提案ボタンを押せる。
- [ ] AC-14: Given 結果の画面, When 「条件を変えてもう一度」を押す, Then 入力の段階に戻り、入力内容は残っている。もう一度提案すると前の結果は置き換わる。

### B. 見た目
- [ ] AC-15: Given 各画面, When 表示する, Then 配色・カード・見出し・入力欄・ボタンが tadasii の画面イメージ(`tadasii/*.png`)と同じ見た目になっている(目視で確認)。
- [ ] AC-16: Given ブラウザ, When アプリを開く, Then タブのタイトルが「はじめてのライブ服」で、アイコンが tadasii のものになっている。
- [ ] AC-17: Given 幅 390px の縦画面と幅 1280px の画面, When 各段階を表示する, Then 横スクロールやはみ出しが無く、広い画面では幅 880px までで中央に表示される。
- [ ] AC-18: Given 出典のリンク, When タップする, Then 出典のページが開く。

### C. 共通
- [ ] AC-19: Given `flutter test`, When 実行, Then Gemini を呼ばずに、段階の切り替え・チェックリストとエラー表示・キャンセル・結果の表示・既存の各機能(MV・ライブ・手持ちの服・提案)の操作を検証できる。`flutter analyze` の警告が 0。
- [ ] AC-20: Given バックエンド, When 本 spec の変更後, Then バックエンドのコード・API に変更が無い。

## 5. 制約 / 前提

- フロントエンドだけを変える(`frontend/`)。API の呼び出し方・送る内容は今と同じにする。
- 参考 UI(`tadasii/`)は別のバックエンド(1 回の送信で提案まで進む API)向けに作られている。
  画面の構成と見た目は tadasii に合わせ、中身(何を入力し、どの API を呼ぶか)は今の機能のままにする。
  tadasii と今の機能が合わない部分(例: tadasii は服の写真を送るだけだが、今は登録・解析して保存する)は、今の機能を tadasii の見た目で表す。
- **spec 011 の「確認タブ」は本 spec で置き換える。** 011 の AC-1〜AC-7(確認タブの表示)は、本 spec の AC-2〜AC-5 と AC-10 で読み替える。
  コーデ提案の条件と動作(011 の AC-8〜AC-14)は変えない。
- 依存の追加は `url_launcher` のみ(承認済み)。
- 依存する spec: [007](../007-youtube-mv-metadata/)、[008](../008-artist-culture-info/)、[009](../009-live-info-search/)、
  [010](../010-wardrobe-registration/)、[011](../011-outfit-suggestion/)。

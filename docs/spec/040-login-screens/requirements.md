# 要件定義: ログイン画面とユーザー登録画面

- ステータス: done
- 作成日: 2026-10-13
- 更新日: 2026-10-13

## 1. 背景 / 課題

spec 038 で、ログインとゲストを作った。そのとき、ログインの入力欄は「③ 手持ちの服」のカードの中に置いた。ヘッダの「ログイン」を押すと、そこまで画面が動く。

この形には次の問題がある。

- ログインの入口が服のカードの中にあるので、「ログインする場所」として分かりにくい。
- ③ のカードに、服の登録とログインの入力欄が混ざって長くなる。
- ユーザー登録の画面が無い。アカウントを持っていない人が、どうすればよいか分からない。

そこで、**ログイン専用の画面と、ユーザー登録の画面を作る**。

ただし、spec 038 の決定(ログインできるのは運営が事前に登録したユーザーだけ)は変えない。
ユーザー登録の画面は**画面だけ**を作り、実際の登録はしない。バックエンドは変えない。

この spec は、038 の決定事項 5「ログインの入力欄は ③ のカードの中に置く」を置き換える。038 の文書は変えない。

## 2. ゴール / 非ゴール

### ゴール

- **ログイン画面(専用の画面)**
  - ヘッダの「ログイン」と、③ の案内の「ログイン」から開く。
  - ユーザー ID とパスワードを入れてログインする。成功したら元の画面に戻る。
  - 誤りの文言・ログインした後の動きは spec 038 と同じ。
  - ゲストのまま戻れる。ユーザー登録の画面へ進める。
- **ユーザー登録画面(画面だけ)**
  - ユーザー ID・パスワード・パスワードの確認を入れる欄と、入力のチェックがある。
  - 「登録する」を押しても、サーバーには送らない。今は登録を受け付けていないことを案内する。
  - ログイン画面へ戻れる。
- **③ のカード**: ゲストの説明と「ログイン」のボタンだけを残し、入力欄は無くす。

### 非ゴール

- 実際のユーザー登録(API・保存)。バックエンド(`backend/`)の変更。
- パスワードの再設定・変更。
- URL でのページの切り替え(ブラウザの URL を `/login` などに変えること)。go_router などの依存の追加。
- ログイン状態の持ち方・期限・ゲストの扱いの変更(spec 038 のまま)。

## 3. ユーザーストーリー

- `アプリの利用者` として、`ログインする場所がすぐ分かる` ようにしたい。なぜなら `服のカードの中にあると見つけにくい` から。
- `アカウントを持っていない利用者` として、`登録の画面を開いて、今は登録できないことと、ゲストで使えることを知りたい`。なぜなら `どうすればよいか迷う` から。
- `アプリの利用者` として、`ログインの途中でやめても、入力した MV やライブが消えない` ようにしたい。

## 4. 受け入れ基準

**ログイン画面**

- [x] AC-1: Given ゲストで入力の段階, When ヘッダの「ログイン」または ③ の「ログイン」を押すと, Then ログイン画面が開く。
  ユーザー ID・パスワードの欄、「ログインする」「ゲストのまま戻る」「新規登録はこちら」が出る。
- [x] AC-2: Given ログイン画面, When 登録済みのユーザー ID と正しいパスワードで「ログインする」を押すと, Then ログイン画面が閉じて元の画面に戻る。
  ヘッダにユーザー ID と「ログアウト」が出て、そのユーザーの服を読み直す(038 AC-1, AC-12)。
- [x] AC-3: Given ログイン画面, When 誤ったパスワード、または登録されていない ID でログインすると, Then 画面は閉じない。
  どちらが誤りか分からない文言を出す(038 AC-2)。接続できないときは「サーバーに接続できませんでした」を出す。
- [x] AC-4: Given ユーザー ID かパスワードが空, When ログイン画面を見ると, Then 「ログインする」は押せない。
  送信中は入力欄とボタンが押せず、ボタンに読み込み中の印が出る。
- [x] AC-5: Given パスワードの欄, When 表示・非表示の切り替えを押すと, Then パスワードの文字が見える / 隠れる。
  パスワードの欄でエンターを押すと「ログインする」と同じ動きをする。
- [x] AC-6: Given ① ② を入力した状態, When ログイン画面を開いて「ゲストのまま戻る」(または端末の戻る操作)で戻る / ログインして戻ると, Then ① ② の入力と選択はそのまま残る。

**ユーザー登録画面(画面だけ)**

- [x] AC-7: Given ログイン画面, When 「新規登録はこちら」を押すと, Then ユーザー登録画面が開く。
  ユーザー ID・パスワード・パスワードの確認の欄、「登録する」「ログイン画面へ戻る」と、今は登録を受け付けていない旨の注記が出る。
- [x] AC-8: Given ユーザー登録画面, When 次の入力で「登録する」を押すと, Then 欄ごとに理由を出し、案内は出さない。
  - ユーザー ID が規則に合わない(英小文字・数字・`_`・`-` の 3〜32 文字。バックエンドの規則と同じ)
  - パスワードが 8 文字未満
  - 確認欄がパスワードと一致しない
- [x] AC-9: Given 規則に合う入力, When 「登録する」を押すと, Then サーバーには何も送らない。
  「現在、新規登録は受け付けていません。ログインできるのは運営が登録したユーザーだけです。ゲストのままでも服の登録とコーデの提案を使えます。」と案内する。
- [x] AC-10: Given ユーザー登録画面, When 「ログイン画面へ戻る」を押すと, Then ログイン画面に戻る。

**③ のカード・共通**

- [x] AC-11: Given ゲスト, When ③ のカードを見ると, Then ゲストの説明(服は 1 日で消える、ログインするとずっと残せる)と「ログイン」のボタンだけが出る。
  ログインの入力欄は出ない。ログインしているときは、この案内は出ない。
- [x] AC-12: Given 幅 390px のスマホの縦画面と PC の幅, When ログイン画面・ユーザー登録画面を開くと, Then はみ出さない。
  部品と配色は、今の画面(spec 015 / 039)と同じものを使う。MV に合わせた配色の最中に開いたら、その配色を引き継ぐ。
- [x] AC-13: Given この spec の変更, When `git diff main -- backend/` を見ると, Then 変更が無い。テストは外部のサービスなしで動く。

## 5. 制約 / 前提

- 技術制約: フロントエンド(Flutter Web)だけを変える。依存ライブラリは増やさない。
- 依存する spec:
  - 038(ログインとゲスト。`AuthSession`・ログインの API)
  - 039(配色の演出。PR #19。この spec のブランチは 039 のブランチから切る)
  - 015(画面のデザイン)

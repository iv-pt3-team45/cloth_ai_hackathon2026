# 要件定義: エージェントループ(生成 → 検証 → 再生成)

- ステータス: approved
- 作成日: 2026-09-17
- 更新日: 2026-09-17

## 1. 背景 / 課題

現在の CLI(spec 002)は 1 往復の対話しかしない。生成物が要望を満たしているかは人間が見て判断し、
不満なら自分で指示し直す必要がある。これを自動化し、**要望を満たすまでエージェントが自律的に繰り返す**ようにする。

## 2. ゴール / 非ゴール

### ゴール
- `scripts/run_agent_loop.py` を実行すると、**生成 → 検証 → 未達なら追加生成 → 検証 …** を自動で繰り返す。
- 検証は要望と生成物を突き合わせて行い、**未達の場合は改善点を次の生成に渡す**。
- 画像・動画の生成物は中身を見て検証する(ファイルの有無だけで判断しない)。
- 繰り返し回数に上限を設け、無限ループしない。
- 各周回の経過(生成内容・判定・理由)が画面で追える。

### 非ゴール
- 対話モード(spec 002 の `run_agent.py` が担当する)。
- 生成物の自動選択 / 削除(全周回の生成物は残す)。
- 人間による中断・介入(承認フロー)。

## 3. ユーザーストーリー

- 利用者として、「〜の画像を作って」と一度頼めば、納得できる品質になるまで自動で試行してほしい。
- 開発者として、何周目で何が問題と判定されたのかを見たい。プロンプトや検証基準の改善に使うため。

## 4. 受け入れ基準

- [x] AC-1: Given 要望, When `uv run python scripts/run_agent_loop.py -m "<要望>"`, Then 生成と検証が繰り返され、最終結果が表示される。
- [x] AC-2: Given 1 周目で要望を満たした場合, When 実行, Then 2 周目に入らず終了する。
- [x] AC-3: Given 要望を満たさない場合, When 次の周回, Then 検証の指摘(改善点)が次の生成指示に含まれる。
- [x] AC-4: Given 上限回数に達した場合, When 実行, Then 未達のまま終了し、その旨が分かる(終了コード 1)。
- [x] AC-5: Given 画像を生成した場合, When 検証, Then 生成された画像そのものを見て判定する。
- [x] AC-6: Given `uv run python -m pytest`, When 実行, Then 外部 API を呼ばずにループの挙動を検証できる。

## 5. 制約 / 前提

- 1 周につき「生成」と「検証」で最低 2 回モデルを呼ぶ。上限回数を大きくするとコストとクォータを消費する。
- 検証モデルは生成モデルと別に設定できるようにする(クォータ分散のため)。
- 生成物は spec 003 の保存先(`app/created_images` / `app/created_videos`)に出力される。

# 要件定義: 画面の調整(解析の画面の配色・文字の見やすさ・アプリ名)

- ステータス: done
- 作成日: 2026-10-13
- 更新日: 2026-10-13

## 1. 背景 / 課題

spec 039(MV に合わせた配色)と spec 040(ログインの画面)をマージした後、本番の画面で次の 3 点が見つかった。

1. **解析の画面だけ配色が変わらない。** ③ で服の写真を入れると「写真の確認」(解析)の画面が開く。MV を選んで配色が変わっていても、この画面だけは標準の配色のままになる。
   原因: 解析の画面は別の画面として開くが、そのときに MV の配色を渡していない。ログインの画面(spec 040)は渡している。
2. **配色によっては文字が見にくい。** spec 039 では差し色を「白い背景に対して」読みやすくしているだけで、それ以外の背景に置いた文字は確かめていない。見にくいのは次の場所(比は手計算の見積もり。読みやすさの目安は 4.5:1 以上)。
   - 送信バーの、入力がそろっていないときのボタン: 薄い差し色の上の白い文字。約 2.6〜2.9:1。標準の配色でも不足している。
   - カードの外(背景の上)のボタン(「キャンセルして入力に戻る」「条件を変えてもう一度」): 暗い背景で、紺・黒系の差し色だと約 1.1〜1.5:1 で、ほぼ見えない。
   - ヘッダの「ログイン」「ログアウト」と説明文: 明るい配色の色付きの背景で約 3.5〜4.4:1。
   - 選んだ候補の「変更」と ✓、カルチャーのカードのリンクと「くわしく見る」: 薄い差し色の背景で約 4.0〜4.2:1。
3. **アプリ名を変えたい。** 「はじめてのライブ服」を「THE FIRST KITAKE」にする。

## 2. ゴール / 非ゴール

### ゴール

- 解析の画面(「写真の確認」)に、MV に合わせた配色を引き継ぐ。背景・上部のバー・ボタンの色を、入力の画面と同じにする。
- どの MV の配色でも、画面の文字(ボタンの文字・リンクを含む)が背景に対して 4.5:1 以上になるようにする。
- 画面に出るアプリ名を「THE FIRST KITAKE」にする。対象は、ヘッダ・ブラウザのタブ・ホーム画面に追加したときの名前。

### 非ゴール

- 配色が切り替わる途中(約 0.4 秒)の色の見やすさ。
- 背景の動き(きらめき・火花など)が文字に重なる見え方。
- アイコン・説明文(「行くライブと手持ちの服から…」)・内部の名前(パッケージ名 `tx_hackathon_gc` など)の変更。
- バックエンドの変更。

## 3. ユーザーストーリー

- `アプリの利用者` として、`写真を登録する画面も MV の雰囲気のまま` にしたい。なぜなら `画面ごとに色がばらばらだと別のアプリのように見える` から。
- `アプリの利用者` として、`どの MV を選んでも、ボタンや文字が読める` ようにしたい。
- `運営` として、`アプリ名を THE FIRST KITAKE で出したい`。

## 4. 受け入れ基準

**解析の画面の配色**

- [x] AC-1: Given MV を選んで配色が変わった状態, When ③ で写真を入れて解析の画面を開くと, Then 解析の画面の配色(差し色・背景のグラデーション・上部のバー)が入力の画面と同じになる。
- [x] AC-2: Given MV を選んでいない、または演出が無い状態, When 解析の画面を開くと, Then 今と同じ標準の配色になる。
- [x] AC-3: Given 暗い配色の解析の画面, When 画面を見ると, Then カードの外の文字(タイトル・「解析中 N / M」・閉じるボタン)が読める(4.5:1 以上)。写真のカードは今と同じ白。

**文字の見やすさ**

- [x] AC-4: Given 色の辞書(spec 039)の色のどれか、または辞書に無い色で配色を作ったとき, When 差し色を確かめると, Then 次の比がすべて 4.5:1 以上になる。
  - 明るい配色: 差し色(accent・accent2)が、白・選んだ項目の背景(selected)・ページの背景に対して。灰色の文字(onBackgroundMuted)がページの背景に対して。
  - 暗い配色: 背景の上の文字(onBackground・onBackgroundMuted)が、ページの背景に対して。背景の上には差し色の文字を置かない(design §5.3)。
- [x] AC-5: Given 入力がそろっていない状態, When 送信バーのボタンを見ると, Then 文字が背景に対して 4.5:1 以上で、そろったときと見た目で区別できる。押すと足りないものを知らせる動きは今のまま。
- [x] AC-6: Given 暗い配色・明るい配色, When 「考え中」の「キャンセルして入力に戻る」と、提案の「条件を変えてもう一度」を見ると, Then 文字と枠が背景に対して読める(文字は 4.5:1 以上)。
- [x] AC-7: Given 明るい配色, When ヘッダの「ログイン」「ログアウト」・説明文を見ると, Then 背景に対して 4.5:1 以上。
- [x] AC-8: Given 標準の配色(MV を選んでいない), When 画面を見ると, Then 配色(`AppPalette.standard`)そのものは今と変わらない。見た目が変わるのは、カードの外の文字(ヘッダの「ログイン」「ログアウト」・「キャンセルして入力に戻る」・「条件を変えてもう一度」。差し色 → 背景用の濃い文字)と、送信バーのボタンだけ(実装中に、標準の差し色も背景に対して約 4.3:1 で足りないと分かったため。2026-10-13)。

**アプリ名**

- [x] AC-9: Given アプリを開いた, When ヘッダ・ブラウザのタブを見ると, Then アプリ名が「THE FIRST KITAKE」になっている。ホーム画面に追加したときの名前(manifest)も同じ。

**共通**

- [x] AC-10: Given この spec の変更, When `git diff main -- backend/` を見ると, Then 変更が無い。テストは外部のサービスなしで動く。

## 5. 制約 / 前提

- 技術制約: フロントエンド(Flutter Web)だけを変える。依存ライブラリは増やさない。
- 読みやすさの基準: WCAG 2 のコントラスト比 4.5:1(通常の文字)。
- 依存する spec:
  - 039(配色の演出。`AppPalette`)
  - 040(ログインの画面。配色の引き継ぎ方)
  - 010(手持ちの服の登録・解析の画面)
  - 015(画面のデザイン・アプリ名)

# 要件定義: MV カードの整理と、カルチャーに合わせた画面の演出

- ステータス: done
- 作成日: 2026-10-08
- 更新日: 2026-10-13

## 1. 背景 / 課題

入力の段階の「① MV を選ぶ」(spec 015)で MV を選ぶと、次のものがすべて縦に並び、画面がとても長くなる。

- 幅 480px の大きいサムネイル
- リンク・動画タイトル・チャンネル・公開日の 4 行と、概要欄
- カルチャー情報の全項目(ファッション・ビジュアル / この MV の衣装 / 経歴・音楽性 / 出典 / 検索候補)
- 選ばなかった MV の候補(選んだ候補の下に残ったまま並ぶ)

そのため、②③ のカードにたどり着くまでのスクロールが長く、コーデに関係する情報(ファッション・衣装)も埋もれている。
また、①②③ のどこまで入力が済んだかは、画面下のチェックリストを見ないと分からない。

さらに、選んだ MV の雰囲気が画面に表れないので、MV を選んだ手応えが薄い。

**画面(フロントエンド)だけを直す。バックエンド・API・カルチャー情報の取得方法は変えない。**
見た目はモック(2026-10-08 にユーザーが確認)を正とする。

## 2. ゴール / 非ゴール

### ゴール

**A. MV の情報を減らす**
- 選んだ動画の情報は、小さいサムネイル・曲名・アーティスト名・「YouTube で開く」のリンクの 1 まとまりにする。
- 動画タイトル・チャンネル・公開日・概要欄は「詳細」を開いたときだけ表示する(初期は閉じている)。
- タイトルを分解できなかったときの注記(spec 007)は今どおり出す。

**B. 候補を選んだら一覧を畳む**
- MV の候補を選ぶと、選んだ 1 件だけを残し、ほかの候補は隠す。
- 選んだ候補の「変更」で候補の一覧に戻る(② のライブ選択の「変更」と同じ動き)。一覧に戻すと、動画の情報とカルチャー情報の表示は消える(今の「閉じる」と同じ)。

**C. カルチャー情報を要点のカードとポップアップに分ける**
- カルチャー情報を調べ終わると、**要点のカード**がアニメーション付きで現れる(小さい状態から弾むように出て、中の項目が順に浮かび上がる)。
- 要点のカードに出すのは、アーティスト名・スタイル・よく使う色(色の丸付き)・この MV の衣装・出典・Google の検索候補。
- 「くわしく見る」を押すと、**下からせり上がるポップアップ**でカルチャー情報の全項目を見られる。
  - 「ファッション」「MV の衣装」「経歴・音楽性」の 3 つのタブに分ける。中身は今のカルチャー情報の項目をすべて含める(減らさない)。
  - 出典と Google の検索候補は、ポップアップの下端に常に表示する(タブを切り替えても消えない)。
  - ✕・背景のタップ・Esc キー(Web)・下へのスワイプで閉じる。
- 調べている途中・失敗(再試行)・アーティストを特定できなかったときの表示は、今の内容のまま残す。

**D. MV のカルチャーに合わせた画面の演出**
- カルチャー情報を調べ終わったら、その「よく使う色」と「スタイル」をもとに、画面の見た目を切り替える。
  - **切り替わりの演出**: 選んだ候補のあたりから、その MV の色が画面いっぱいに広がって消える(1 回だけ)。
  - **配色**: 画面の背景(グラデーション)・ボタン・番号の丸・選択中の枠・タブの下線などの差し色を、その MV の色にする。
  - **背景の動き**: スタイルに合わせた動きを、カードの後ろの背景で流し続ける。用意する種類は次の 4 つ。

    | 演出 | 動き | 合うスタイルの例 |
    | --- | --- | --- |
    | きらめき | 星とハートが舞い上がる | ガーリー・ポップ・キュート・アイドル |
    | 火花 | 火花が上がり、照明のように明滅する(暗い背景) | ロック・パンク・ハード |
    | 花びら | 花びらがゆっくり舞い落ちる | ナチュラル・レトロ・フォーク |
    | ネオン | 光の粒が線を描いて流れる(暗い背景) | エレクトロ・クラブ・ダンス・サイバー |

  - ポップアップの上部と、要点カードの背景も、その MV の色に合わせる。
  - 「2 AIが考え中」「3 提案」の段階にも、背景と差し色を引き継ぐ(画面のレイアウトは変えない)。
- **文字を読むカード(①②③ の白いカード・ポップアップの本文)は白地のまま**にし、どの MV でも文字の読みやすさを変えない。
- どの演出にも当てはまらないとき(スタイルの言葉が合わない・色が取れない・アーティストを特定できない・取得に失敗)は、
  **今の配色のまま、演出なし**で表示する。色だけ取れたときは配色だけ変える。
- 「変更」で MV の選択を外したら、元の配色に戻し、背景の動きも止める。
- 端末で動きを減らす設定(OS の「視差効果を減らす」など)が有効なときは、配色だけ切り替え、切り替わりの演出と背景の動き、
  要点カード・ポップアップのアニメーションは行わない。

**E. 操作しやすくする**
- ①②③ のカードの番号の丸を、入力が済んだら ✓(緑)に変える。
  - ①: MV を選んで動画の情報が出ている / ②: ライブを 1 件選んでいる / ③: 手持ちの服が 1 点以上ある
- カルチャー情報を調べている間は、① の検索ボタンの下と ② の検索ボタンの下に、
  「カルチャー情報を調べ終わるまで、検索・選び直しはできません」という趣旨の理由を出す(入力を止める条件そのものは変えない)。

### 非ゴール
- バックエンド・API・カルチャー情報の取得内容の変更。演出の判定のために Gemini を呼び直すこともしない。
- 右上などに「〇〇 モード」のような演出の名前を出すこと(ユーザー確認で不要)。
- 演出を利用者が切り替える設定(オン / オフ)。
- 「2 AIが考え中」「3 提案」の段階の画面の作り変え(配色が引き継がれる以外は変えない。未決事項 2 で決定)。
- ② のライブ・③ の手持ちの服のカードの中身の変更(✓ と理由の表示を除く)。
- ダークモード。

## 3. ユーザーストーリー

- ライブに行く利用者として、MV を選んだら次の入力にすぐ進みたい。MV の細かい情報は普段は見ないから。
- ライブに行く利用者として、カルチャー情報のうちコーデに関係するところをまず見たい。経歴などは気になったときに読めればよいから。
- ライブに行く利用者として、MV を選んだら画面がそのアーティストらしい雰囲気になってほしい。ライブに行く気分が高まるから。
- ライブに行く利用者として、①②③ のどこまで済んだかを見ただけで分かりたい。次に何をすればよいか迷わないから。

## 4. 受け入れ基準

**A. MV の情報**
- [ ] AC-1: Given MV を選んで動画の情報が出ている, When 画面を見る, Then 小さいサムネイル・曲名・アーティスト名・「YouTube で開く」が出ており、動画タイトル・チャンネル・公開日・概要欄は出ていない
- [ ] AC-2: Given AC-1 の状態, When 「詳細」を押す, Then 動画タイトル・チャンネル・公開日・概要欄が出る。もう一度押すと閉じる
- [ ] AC-3: Given AC-1 の状態, When 「YouTube で開く」を押す, Then 動画の URL が開く(開けなければ「リンクを開けませんでした」)

**B. 候補一覧**
- [ ] AC-4: Given MV 名で検索して候補が複数ある, When 候補を 1 件選ぶ, Then 選んだ候補だけが残り、ほかの候補は表示されない
- [ ] AC-5: Given AC-4 の状態, When 「変更」を押す, Then 候補の一覧に戻り、動画の情報とカルチャー情報は消える
- [ ] AC-6: Given カルチャー情報を調べている, When 「変更」を押す, Then 何も起きない(今と同じく取得中は操作できない)

**C. 要点のカードとポップアップ**
- [ ] AC-7: Given カルチャー情報を調べ終わった, When 画面を見る, Then 要点のカード(アーティスト名・スタイル・よく使う色・この MV の衣装・出典・検索候補・「くわしく見る」)が出る
- [ ] AC-8: Given AC-7 の状態, When 「くわしく見る」を押す, Then 下からポップアップが開き、「ファッション」タブが選ばれている
- [ ] AC-9: Given ポップアップが開いている, When 各タブを押す, Then ファッション(スタイル・よく使う色・定番のアイテム・世界観・出典番号)/ MV の衣装(シーンごとの衣装・根拠)/ 経歴・音楽性(概要・活動の歩み・ジャンル・代表曲・音楽的な特徴・出典番号)が切り替わって出る
- [ ] AC-10: Given ポップアップが開いている, When どのタブを選んでいても, Then 下端に出典と Google の検索候補が出ている
- [ ] AC-11: Given ポップアップが開いている, When ✕ / 背景 / 下へのスワイプで閉じる, Then ポップアップが閉じ、入力の画面に戻る
- [ ] AC-12: Given カルチャー情報の取得に失敗した / アーティストを特定できなかった, When 画面を見る, Then 今と同じ内容(再試行ボタン / 特定できなかった旨と出典・検索候補)が出る

**D. 演出**
- [ ] AC-13: Given スタイルに「ガーリー」を含むカルチャー情報が届いた, When 画面を見る, Then 差し色がよく使う色に基づく色になり、背景で「きらめき」が流れる
- [ ] AC-14: Given スタイルに「ロック」を含むカルチャー情報が届いた, When 画面を見る, Then 背景が暗くなり「火花」が流れる。白いカードの文字の色は変わらない
- [ ] AC-15: Given スタイルがどの演出にも当てはまらず、色も取れない, When カルチャー情報が届く, Then 配色も背景も今のまま変わらない
- [ ] AC-16: Given 演出が出ている, When ① の「変更」で MV の選択を外す, Then 元の配色に戻り、背景の動きが止まる
- [ ] AC-17: Given 端末で動きを減らす設定が有効, When カルチャー情報が届く, Then 配色だけが変わり、切り替わりの演出・背景の動き・カードとポップアップのアニメーションは出ない
- [ ] AC-21: Given 演出が出ている, When 「コーディネートを提案してもらう」を押して「2 AIが考え中」「3 提案」に進む, Then 背景と差し色が引き継がれ、画面のレイアウトは今と変わらない

**E. 操作性**
- [ ] AC-18: Given ①②③ のいずれかの入力が済んだ, When 画面を見る, Then そのカードの番号の丸が緑の ✓ になる。済んでいないカードは番号のまま
- [ ] AC-19: Given カルチャー情報を調べている, When 画面を見る, Then ① と ② の検索ボタンの下に、調べ終わるまで操作できない理由が出る。調べ終わると消える

**共通**
- [ ] AC-20: `backend/` のファイルに変更が無い。既存の API の呼び出し方・コーデ提案に送る内容(MvLookupSnapshot)も変わらない

## 5. 制約 / 前提

- フロントエンド(`frontend/`)だけを変更する。
- 演出の判定に使うのは、今のカルチャー情報の応答の `fashion.colors`(色の名前)と `fashion.styles`(スタイルの言葉)だけ。
  色の名前 → 色の値、スタイルの言葉 → 演出の種類 の対応は、画面の側(Dart)に持つ。Gemini の応答は言い回しが毎回少し違うため、
  言葉の部分一致で判定し、外れたら「演出なし」に倒す。
- Google の検索候補は利用条件により表示が必須(README 4.9)。畳んだり隠したりしない。
- 背景の動きは Web(CanvasKit)のスマホでも重くならない量に抑える(粒の数を数十程度にする)。
- 依存する spec: 007(MV のメタ情報)/ 008(カルチャー情報)/ 009(ライブ情報)/ 015(画面の作り直し)

# 要件定義: プライバシーポリシーの画面

- ステータス: approved
- 作成日: 2026-10-13
- 更新日: 2026-10-13(サービス名や期間などの具体的な値を書かないことにした。決定事項 5)

## 1. 背景 / 課題

このアプリ(「はじめてのライブ服」)は、利用者が手持ちの服の写真を登録し、それを AI(Gemini)で解析・保存して、コーデの提案や
マネキンに着せた画像の生成に使う(spec 010・011・036)。公開した画面(spec 035)は誰でも使えるが、
**利用者の写真や入力した文字をどう扱うかを説明する場所が無い**。

今の main での扱い(ポリシーに書く事実。design で実装と突き合わせる):

| 情報 | 扱い |
| --- | --- |
| 服の写真 | 画面で縮小して API に送る。Gemini(Google Cloud の Vertex AI)で属性を読み取る。保存すると Cloud Storage(東京リージョン、非公開のバケット)に残る |
| 服の属性(種類・素材・色など。利用者が直した内容を含む) | 写真と一緒に保存し、コーデ提案のときに Gemini に送る |
| 登録した服の共有 | **ログインが無いため、登録した服(写真と属性)はアプリを使う全員で共有される**。他の人の一覧に表示され、他の人のコーデ提案にも使われる |
| 削除 | 利用者が一覧の × で 1 点ずつ削除できる。Cloud Storage の写真は、削除後 7 日間は復元できる状態で残る(バケットのソフト削除の既定) |
| 入力した文字 | MV の URL・曲名は YouTube Data API へ、ライブの検索語・アーティストは Gemini(Google 検索つき)へ送る |
| 生成したコーデ画像 | サーバー(Cloud Run)の一時的な領域に保存する(サーバーが止まると消える) |
| 通信・処理の記録 | Cloud Run などが通信の記録(IP アドレス・ブラウザの種類・日時など)を残す。障害の調査のため、エラーの内容などをログに残す |
| 集めないもの | 氏名・メールアドレス・アカウント。分析ツール(Google Analytics など)や広告は使っていない |

## 2. ゴール / 非ゴール

### ゴール
- 初期ページ(入力の段階)の**一番下に、小さめの灰色の文字で「プライバシーポリシー」**のボタン(リンク)を置く。
- 押すと、**アプリ内のプライバシーポリシーの画面**が開く。今の画面と同じ配色・カードのデザインで、戻るボタンで初期ページに戻れる。
  戻ったとき、入力した内容・選んだ候補・登録した服の表示は残っている。
- ポリシーには、次の項目を**今の main の実装どおりに**書く(上の表の内容)。ただし外部のサービスの名前や、保存の日数などの具体的な値は書かず、
  一般的な言い方にする(決定事項 5)。
  1. はじめに(本アプリと運営者)
  2. 取り扱う情報
  3. 利用目的
  4. 外部のサービスへの送信(AI・動画や検索・クラウドのサービスに送ること。サービスの名前は書かない)
  5. 保存する期間と削除の方法(日数は書かない)
  6. 登録した服が他の利用者と共有されること
  7. 写真を登録するときのお願い(人の顔・名前・住所など個人が分かるものが写った写真、他人の写真を登録しない)
  8. 第三者への提供(法令に基づく場合などを除き、上記以外に提供しない)
  9. 安全のための取り組み(通信の暗号化・非公開の保存先)
  10. ポリシーの変更と制定日
  11. 運営者
- 運営者は「テックドロップ」と書く(決定事項 7)。問い合わせ先の項目は作らない。

### 非ゴール
- バックエンドの変更(ポリシーは画面の中に持つ)。
- 別の Web ページ(`privacy.html` など)としての公開。ポリシーの URL を直接共有する仕組み。
- 写真を登録する前の同意(チェックボックスなど)や、初回に表示するポップアップ。
- 利用規約(使い方の決まり)のページ。
- 写真の位置情報(Exif)を消す処理など、データの扱いそのものの変更(必要なら別の spec)。
- 法律の専門家による内容の確認(ハッカソンの試作のため)。
- spec 038(ログイン)の内容の先取り。038 がマージされたら、共有・削除・保存期間の記述を 038 の動きに合わせて直す(5. 制約)。

## 3. ユーザーストーリー

- `アプリの利用者` として、`服の写真がどこに送られ、いつまで残り、誰に見えるのか` を写真を登録する前に確かめたい。なぜなら `自分の持ち物の写真を預けるから`。
- `運営(チーム)` として、`データの扱いを正直に説明` しておきたい。なぜなら `公開したアプリで利用者の写真を扱っているから`。

## 4. 受け入れ基準

- [x] AC-1: Given 初期ページ(入力の段階), When 一番下までスクロールすると, Then ③ 手持ちの服のカードの下に、小さめの灰色の文字で「プライバシーポリシー」が出る。スマホの幅と PC の幅のどちらでも、提案ボタンのバーに隠れない。
- [x] AC-2: Given 初期ページ, When 「プライバシーポリシー」を押すと, Then アプリ内のプライバシーポリシーの画面が開き、2. の 11 項目が今の画面と同じデザインで読める。
- [x] AC-3: Given プライバシーポリシーの画面, When 戻るボタン(画面上部の ← と、ブラウザの戻る)を押すと, Then 初期ページに戻り、入力した MV・選んだライブ・登録した服の表示が残っている。
- [x] AC-4: Given ポリシーの文, When 今の main の実装と比べると, Then 1. の表の内容(共有・削除するまで保存・削除後もしばらく復元できること・外部のサービスに送ること・集めないもの)と食い違いが無い。サービスの名前や日数などの具体的な値は書かれていない。
- [x] AC-5: Given AI が考え中・提案の段階, When 画面を見ると, Then 「プライバシーポリシー」は出ない(初期ページだけに置く)。
- [x] AC-6: Given `flutter test`, When 実行すると, Then 初期ページにリンクがあること、押すとポリシーの画面が開くこと、戻ると入力が残っていることを確認できる。`flutter analyze` の警告が無い。
- [x] AC-7: Given README, When チームメンバーが読むと, Then ポリシーの置き場所と、データの扱いを変えたとき(spec 038 のマージなど)にポリシーも直す決まりが分かる。

## 5. 制約 / 前提

- 依存の追加なし。画面の部品は spec 015 の `lib/core/theme.dart` / `widgets.dart` を使う。
- ポリシーの内容は**今の main**(ログインなし・服は全員で共有)に合わせる(2026-10-13 ユーザー決定。ブランチ `feat/042-privacy-policy`)。
  別ブランチの spec 038(ログイン・ゲストの服は 1 日で消える)が先にマージされた場合は、このブランチに main を取り込んでから 038 に合わせて書き直す。
  042 が先にマージされた場合は、038 のマージ時にポリシーを直す。
- データの扱い(保存先・共有・保存期間・外部のサービス)を変える spec は、同じ変更でポリシーの文も直す(README に決まりとして書く)。
- 依存する spec: 010(服の登録)、011(コーデ提案)、015(画面のデザイン)、035(公開)、036(Cloud Storage への保存)、037(入力のチェック)。

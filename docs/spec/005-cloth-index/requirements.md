# 要件定義: 服画像のインデックス作成

- ステータス: approved
- 作成日: 2026-09-17
- 更新日: 2026-09-17

## 1. 背景 / 課題

手持ちの服を撮影した画像はあるが、機械的に扱える情報になっていない。
コーディネート提案や検索を行う前提として、**画像から服の属性を抽出してインデックス化**する必要がある。

## 2. ゴール / 非ゴール

### ゴール
- 指定ディレクトリ内の画像を 1 枚ずつ読み込み、**素材・形・色・系統**を抽出する。
- 抽出結果を **1 つの JSON ファイル**(`index.json`)にまとめて保存する。
- 1 枚に複数の服が写っている場合も、服ごとに分けて記録する。
- 既に処理済みの画像は再実行時にスキップする(モデル呼び出しを無駄にしないため)。

### 非ゴール
- インデックスを使った検索・コーディネート提案(次の spec で扱う)。
- データベースへの保存(現状は JSON ファイル)。
- 服以外(小物・靴)の分類精度の作り込み。
- フロントエンドからの利用。

## 3. ユーザーストーリー

- 利用者として、服の写真を置いておくだけで属性一覧が出来てほしい。手入力したくないため。
- 開発者として、抽出項目を後から増やしたい。スキーマが 1 箇所にまとまっていてほしい。

## 4. 受け入れ基準

- [x] AC-1: Given `backend/tests/sample_images/` の画像, When インデックス作成を実行, Then 各画像について素材・形・色・系統が抽出される。
- [x] AC-2: Given 実行後, When `backend/tests/sample_cloth_indexs/` を見る, Then `index.json` 1 ファイルに全画像の結果がまとまっている。
- [x] AC-3: Given 1 枚に複数の服が写る画像, When 実行, Then 服ごとに項目が分かれて記録される。
- [x] AC-4: Given 既に結果がある画像, When 再実行, Then スキップされる(`--force` で再作成できる)。
- [x] AC-5: Given 画像以外のファイルが混ざっている, When 実行, Then 無視される。
- [x] AC-6: Given `uv run python -m pytest`, When 実行, Then 外部 API を呼ばずに保存処理を検証できる。

## 5. 制約 / 前提

- 抽出はモデルの推定であり、素材などは見た目からの推測になる(断定できない場合は「不明」を許容する)。
- 認証は ADC。画像は spec 002 の添付と同じくインラインでモデルに渡す。

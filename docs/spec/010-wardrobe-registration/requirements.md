# 要件定義: 手持ちの服の写真を登録する

- ステータス: approved
- 作成日: 2026-09-30
- 更新日: 2026-09-30

## 1. 背景 / 課題

最終的な目的は、ライブ(spec 009)・アーティストのカルチャー(spec 008)・当日の天気に合わせて、
**手持ちの服から最適な服装を提案する**こと(後続の spec)。

しかし現状、服のインデックスは spec 005 の CLI で開発者がサンプル画像から作るだけで、
**利用者がアプリから自分の服を登録する手段がない**。
また、服装の提案に必要な「季節・暖かさ・使う場面」の情報も持っていない。

## 2. ゴール / 非ゴール

### ゴール
- **新しいタブ「手持ちの服」**を下部のナビゲーションに追加する(MV 検索・チャットとは別)。
- 服の写真を **1 枚または複数枚まとめて**選ぶと、Gemini が **1 枚ずつ順に**解析し、服ごとの属性(文字情報)にする。
- **保存前に**解析結果を写真と並べて表示し、利用者が属性を直したり、写真ごと・服ごとに登録から外したりできる。
- 確定した服の**属性(インデックス)と写真**を、バックエンドのローカルファイルに保存する。形式は spec 005 の `index.json` を拡張したもの。
  将来 Cloud(Cloud Storage / Firestore など)に移せるよう、保存処理は差し替えられる形にする。
- 登録済みの服を写真と属性で**一覧表示**し、**削除**できる(削除の単位は服 1 点)。
- 登録した服は、チャットのエージェント(spec 006)からも参照できる(後続のコーデ提案でも使う)。

### 抽出する項目

| 項目 | 値の決め方 | 例 |
| --- | --- | --- |
| 種類・素材・形・柄・特徴 | 自由な語(spec 005 と同じ。素材は「不明」可) | Tシャツ / 綿 / 半袖クルーネック |
| 色 | 自由な語・複数(目立つ順) | 白、紺 |
| 系統 | 自由な語(spec 005 と同じ) | カジュアル、ストリート |
| **季節(追加)** | 選択肢・複数: 春 / 夏 / 秋 / 冬 | 春、秋 |
| **暖かさ(追加)** | 選択肢・1 つ: 薄手 / 普通 / 厚手 | 薄手 |
| **使う場面 TPO(追加)** | 選択肢・複数: 普段着 / きれいめ(食事・オフィス) / フォーマル / スポーツ・アウトドア / ライブ・フェス | 普段着、ライブ・フェス |

- 季節・暖かさ・使う場面は、ライブ当日の天気(spec 009)や場面と照合しやすいよう、**決まった選択肢**から選ぶ。
  Gemini はこの選択肢の中から選び、利用者は保存前に直せる。
- 1 枚に複数の服が写っていれば、服ごとに分けて扱う(spec 005 と同じ)。

### 非ゴール
- 服装の提案そのもの(後続の spec)。
- 保存後の属性の編集(保存前の確認・修正のみ。直すときは削除して登録し直す)。
- Cloud への保存、複数の利用者(ログイン)への対応(今は 1 人の利用者がローカルで使う前提)。
- 重複登録の検出、写真の加工(背景除去・切り抜き)。
- jpg / png / webp 以外の形式(HEIC など)。
- spec 005 の CLI の変更(サンプル画像からのインデックス作成はそのまま)。

## 3. ユーザーストーリー

- 利用者として、手持ちの服を写真に撮って登録したい。後で自分の服から服装を提案してもらうため。
- 利用者として、何枚かまとめて登録したい。1 枚ずつは手間だから。
- 利用者として、Gemini の解析が間違っていたら保存前に直したい。間違った情報で提案されたくないから。
- 利用者として、登録した服を一覧で確認し、手放した服は消したい。

## 4. 受け入れ基準

未チェックの AC(画面の表示・操作)は、自動テスト(フェイクの Repository / PhotoPicker)と実 API(tasks.md の T-08)では確認済み。
ブラウザでの目視確認(T-09)が済んだらチェックする。

- [ ] AC-1: Given アプリを開いている, When 下部のナビゲーションを見る, Then MV 検索・チャットとは別に「手持ちの服」タブがある。
- [ ] AC-2: Given 服の写真 1 枚以上(jpg / png / webp), When 選んで解析する, Then 1 枚ずつ Gemini で解析され、写真ごとに服の属性(2. の項目)が表示される。解析中は何枚目かが分かる。
- [ ] AC-3: Given 1 枚に複数の服が写っている写真, When 解析する, Then 服ごとに分かれて表示される。
- [ ] AC-4: Given 解析結果, When 属性を直す(自由な語は書き換え、季節・暖かさ・使う場面は選択肢から選ぶ), Then 直した内容で保存される。
- [ ] AC-5: Given 解析結果, When 写真または服を登録から外して保存する, Then 外したものは保存されない。
- [x] AC-6: Given 確認した解析結果, When 保存する, Then 服の属性と写真がバックエンドのローカルに保存され、アプリやサーバを再起動しても一覧に残る。
- [ ] AC-7: Given 保存前の解析結果, When 保存しないまま確認を取りやめる, Then 何も保存されない。
- [ ] AC-8: Given 登録済みの服, When 「手持ちの服」タブを開く, Then 写真と主な属性(種類・色・系統・季節など)の一覧が表示される。0 件なら登録を促す表示になる(既存のサンプルは取り込まないため、初回は 0 件)。
- [x] AC-9: Given 登録済みの服, When 削除する(確認あり), Then 一覧から消え、エージェントからも参照されなくなる。
- [x] AC-10: Given 登録した服, When チャットで「手持ちの服を教えて」と聞く, Then 登録した服を踏まえて答える(spec 006 の参照先が登録した服になる)。
- [x] AC-11: Given 服が写っていない写真・対応していない形式・大きすぎる写真, When 解析する, Then その写真だけエラーになり、他の写真の解析は続く。
- [x] AC-12: Given Gemini の失敗(クォータ超過など), When 解析する, Then その写真にエラーと再解析の手段が出る。
- [x] AC-13: Given `uv run python -m pytest` と `flutter test`, When 実行, Then Gemini を呼ばずに、解析結果の解釈・保存・一覧・削除・画面の状態の切り替えを検証できる。

## 5. 制約 / 前提

- Gemini は Vertex AI 経由(認証は ADC)。画像はリクエストに載せて渡す(spec 002 / 005 と同じインライン)。
- 保存先はバックエンドのローカルファイル(Git 管理外)。Docker Compose ではホストの `backend/` がマウントされるため残る。
  Cloud Run などに載せると再起動で消える(将来 Cloud に移す。未決事項 1)。
- 1 人の利用者が前提(認証なし。今のアプリ全体と同じ)。
- 1 枚の上限サイズと、1 回にまとめて選べる枚数の上限を設ける(値は design で決める。未決事項 2)。
- 解析は 1 枚ずつ順に行う(クォータの瞬間的な消費を避けるため。spec 005 と同じ)。
- 外部 API(Gemini)の呼び出しは `app/services/` に閉じ、テストではスタブにする。
- 依存する spec: [005-cloth-index](../005-cloth-index/)(属性と `index.json` の形式)、[006-wardrobe-tools](../006-wardrobe-tools/)(エージェントの参照)。
  後続の服装の提案で [008-artist-culture-info](../008-artist-culture-info/) / [009-live-info-search](../009-live-info-search/) と組み合わせる。

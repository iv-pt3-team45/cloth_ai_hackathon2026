# 要件定義: 情報の確認タブと、手持ちの服からのコーデ提案

- ステータス: approved
- 作成日: 2026-10-02
- 更新日: 2026-10-02

## 1. 背景 / 課題

spec 007〜010 で、次の情報が揃うようになった。

| 情報 | spec | 取得する場所 |
| --- | --- | --- |
| MV の情報(曲名・アーティスト・リンク) | 007 | MV 検索タブ |
| アーティストのカルチャー情報(ファッション・経歴・音楽ジャンル・MV の衣装) | 008 | MV 検索タブ(動画を選ぶと自動) |
| ライブ情報と当日の天気 | 009 | MV 検索タブ(「ライブを探す」で選ぶ) |
| 手持ちの服 | 010 | 手持ちの服タブ |

しかし情報が別々のタブに散らばっていて一度に見渡せず、最終目的である
**「行くライブに合わせて、手持ちの服からコーデを提案する」**ことがまだできない。

## 2. ゴール / 非ゴール

### ゴール

**A. 確認タブ**
- 下部のナビゲーションに「**確認**」タブを追加する。他のタブで入力・取得した情報を**表示専用**でまとめて確認できる。

| 表示する情報 | 内容 |
| --- | --- |
| 入力 | MV 検索タブで入力した MV 名 / URL、ライブ検索の条件(ライブ情報・日付) |
| MV 情報 | 表示中の動画(サムネイル・曲名・アーティスト名・リンク) |
| アーティスト情報 | 特定したアーティスト名と概要 |
| カルチャー情報 | **MV のファッション**(ファッション・ビジュアルの傾向と「この MV の衣装」)と**音楽ジャンル** |
| ライブ情報 | 選んだライブ(ライブ名・場所・日付)と**当日の天気** |
| 手持ちの服 | **小さな写真の横並び**。横にスクロールして全件を見られる。**1 画面に並ぶ枚数は画面の幅から決める** |

- まだ取得していない情報は「まだありません」と、どのタブで取得するかを案内する。
- 他のタブで内容が変わったら、確認タブの表示にも反映する。

**B. コーデ提案**
- 確認タブに「**コーデを提案**」ボタンを置く。**手持ちの服が 1 点以上・MV(動画情報)・選んだライブ**がそろったときだけ押せる。
- 押すと、**手持ちの服のインデックス・MV 情報・アーティスト情報・カルチャー情報・ライブ情報・天気**を Gemini に渡し、
  Gemini が総合的に判断して、**手持ちの服の中から 1 コーデ**を提案する。
- **手持ち以外の服は提案に含めない**(Gemini が手持ちに無い服を返しても、表示にも画像の生成にも使わない)。
- 提案したコーデをもとに、**Nano Banana 2 Flash Lite**(`IMAGE_MODEL`)で、**マネキン画像に提案の服を着せた画像**を 1 枚生成する。
  画像の生成では、服のインデックス(文字情報)ではなく、**登録した服の写真そのもの**を参照として渡す。
- 画面には、提案(使う服の小さな写真と理由)と生成した画像を表示する。もう一度押すと提案し直す。

### 非ゴール
- 手持ち以外の服(買い足す服)の提案。
- 複数のコーデ案の提示(1 案のみ)。
- 提案・画像の履歴の一覧や保存の管理(生成した画像のファイルは spec 003 と同じ保存先に残る)。
- 確認タブでの情報の編集(編集は各タブで行う)。
- マネキン以外(利用者本人や実在の人物)への着せ替え。

## 3. ユーザーストーリー

- 利用者として、選んだ MV・アーティスト・ライブ・天気・手持ちの服を 1 画面で見渡したい。何が揃っていて何が足りないか分かるように。
- 利用者として、行くライブに合わせたコーデを、自分が持っている服だけで提案してほしい。買い足さずに済ませたいから。
- 利用者として、提案されたコーデを着た姿を画像で見たい。組み合わせの雰囲気を確かめたいから。

## 4. 受け入れ基準

### A. 確認タブ
- [ ] AC-1: Given アプリを開いている, When 下部のナビゲーションを見る, Then 「確認」タブがある。
- [ ] AC-2: Given MV 検索タブで MV を表示し、ライブを検索した, When 確認タブを開く, Then 入力した MV 名 / URL とライブ検索の条件、動画情報、アーティスト情報が表示される。
- [ ] AC-3: Given カルチャー情報を取得した, When 確認タブを開く, Then MV のファッション(ファッション・ビジュアルの傾向と「この MV の衣装」)と音楽ジャンルが表示される。
- [ ] AC-4: Given ライブの候補を 1 件選んだ, When 確認タブを開く, Then 選んだライブのライブ名・場所・日付と当日の天気が表示される。
- [ ] AC-5: Given 手持ちの服が登録されている, When 確認タブを開く, Then 服が小さな写真で横に並び、横にスクロールして全件を見られる。1 画面に並ぶ枚数は画面の幅に応じて変わる(例: スマホ幅で 4 枚、PC 幅で 8 枚)。
- [ ] AC-6: Given まだ取得していない情報がある, When 確認タブを開く, Then その欄に「まだありません」と、どのタブで取得するかが表示される。
- [ ] AC-7: Given 他のタブで情報が変わった(別の MV・別のライブを選んだ、服を登録・削除した), When 確認タブを開く, Then 新しい内容が表示される。

### B. コーデ提案
- [ ] AC-8: Given 手持ちの服・MV・選んだライブのどれかが足りない, When 確認タブを見る, Then 「コーデを提案」は押せず、足りないものが示される。
- [ ] AC-9: Given 必要な情報がそろっている, When 「コーデを提案」を押す, Then Gemini が手持ちの服・MV・アーティスト・カルチャー・ライブ・天気をもとに 1 コーデを提案し、使う服(小さな写真)と理由が表示される。
- [ ] AC-10: Given Gemini が手持ちに無い服を返した, When 提案を表示する, Then 手持ちに無い服は表示にも画像の生成にも使われない。
- [ ] AC-11: Given 提案が出た, When 続けて画像を生成する, Then マネキン画像に提案の服を着せた画像が表示される。生成には登録した服の写真そのものが参照として渡される。
- [ ] AC-12: Given 提案・画像の生成中, When 画面を見る, Then ローディングが表示され、「コーデを提案」は押せない。
- [ ] AC-13: Given 提案に失敗した, When 画面を見る, Then エラーと再試行ボタンが出る。画像の生成だけ失敗した場合は、提案は表示したまま画像の欄にエラーと再生成ボタンが出る。
- [ ] AC-14: Given 提案を表示している, When もう一度「コーデを提案」を押す, Then 新しく提案と画像の生成をやり直し、前の結果は置き換わる。
- [ ] AC-15: Given `uv run python -m pytest` と `flutter test`, When 実行, Then Gemini を呼ばずに、入力の組み立て・手持ち以外の服の除外・エラーの変換・画面の状態の切り替えを検証できる。

## 5. 制約 / 前提

- 提案は Gemini(Vertex AI、認証は ADC)。画像の生成は Nano Banana 2 Flash Lite(`IMAGE_MODEL`。spec 003 と同じ)。
- 画像の生成には、**マネキン画像と、提案に使う服の写真**を入力として渡す。1 枚の写真に複数の服が写っている場合は、どの服を使うかを指示文で伝える。
- マネキン画像は `backend/app/assets/white_manekin.jpeg` に移して Git で管理する(場所は設定で変えられる)。
- 提案には Google 検索を使わない(すでに取得した情報を使う)。カルチャー情報・ライブ情報は保存せず、画面が持っている内容をそのまま渡す(spec 008 / 009 の「保存しない」方針を守る)。
- 確認タブは他のタブの状態を表示するため、タブをまたいで状態を共有する仕組みが要る(design で決める)。
- 処理時間は、提案で数秒〜十数秒、画像の生成で十数秒〜数十秒を想定する。
- 外部 API(Gemini)の呼び出しは `app/services/` に閉じ、テストではスタブにする。
- 依存する spec: [003](../003-media-generation-tools/)(画像の生成)、[007](../007-youtube-mv-metadata/)、[008](../008-artist-culture-info/)、
  [009](../009-live-info-search/)、[010](../010-wardrobe-registration/)。

## 6. 決定事項 / 未決事項

### 決定事項(2026-10-02)

| # | 論点 | 決定 |
| --- | --- | --- |
| 1 | 「コーデを提案」を押せる条件 | 手持ちの服 1 点以上・MV(動画情報)・選んだライブがそろったとき。カルチャー情報と天気は取得できている範囲で使う |
| 2 | 手持ちの服の横並びの「一度に表示できる最大数」 | 1 画面に並ぶ枚数のこと。画面の幅から決め、残りは横スクロールで見る |
| 3 | マネキン画像の置き場所 | `backend/app/assets/` に移して Git で管理する |
| 4 | 提案の数と画像 | 1 案と、その画像 1 枚。押し直せば作り直す |
| 5 | 提案に使う文字のモデル | `GEMINI_MODEL` とは別に `OUTFIT_MODEL` を設ける(design.md 6.3) |
| 6 | 1 画面に並ぶ枚数 | 幅 600 未満で 4 枚、1024 未満で 6 枚、それ以上で 8 枚(design.md 5.3) |
